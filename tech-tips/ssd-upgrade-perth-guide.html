This is the upgrade that makes the biggest difference, because a mechanical drive is by far the slowest part of most computers built in the last decade. It reads data with a physical arm moving across a spinning disk, and Windows reads thousands of small files just to start up, which is exactly the kind of work a mechanical drive handles worst.

The difference is not subtle. A machine that takes a minute and a half to reach the desktop on a mechanical drive typically boots in well under twenty seconds on an SSD, and programs that used to take ten or twenty seconds to open tend to appear in two or three. Everything else about the machine can be unchanged and it will still feel like a different computer.

- id: drive-also-failing title: "The drive is not just old, it has started showing failure signs" urgency: stop-now urgency_label: "Stop using it now" price_key: data-recovery-failing-drive text: |

If the drive is also clicking, freezing the machine at random, or throwing file errors it did not used to, speed is no longer the main concern. Those are the signs of a drive that is actually failing, not just an old one that is slow, and an upgrade done on a failing drive can lose data in the process of copying it across.

In this situation the order matters: whatever can still be read off the old drive needs to come off it safely first, and the SSD goes in once that is done. Treating a failing drive as a routine upgrade risks losing exactly the files the upgrade was meant to speed up access to.

- id: small-early-ssd title: "An early, small SSD that is now almost full" urgency: can-wait urgency_label: "Can wait" price_key: ssd-upgrade-labour-only text: |

Early SSDs were often fitted in small sizes to keep the cost of the upgrade down, and a drive running close to completely full slows down noticeably: it has less room to manage itself efficiently, and Windows starts struggling to find contiguous space for updates and temporary files. This can feel a lot like a machine that has never been upgraded at all.

The fix is a larger SSD rather than a different kind of drive, with everything cloned across the same way a first upgrade would be. It is rarely urgent, since a full drive degrades gradually rather than failing outright, but it is worth doing before it gets bad enough to affect everyday use.

- id: gaming-creative-loads title: "Long load times in games or creative software specifically" urgency: can-wait urgency_label: "Can wait" price_key: ssd-upgrade-labour-only text: |

Some slowness is about the whole system, and some is specific to how fast large files can be read off the drive: game levels loading, textures appearing gradually, or a video editor taking a long time to open a project. If Windows itself feels fine but specific programs are slow to load their own content, storage speed is usually the reason.

This matters most for software and games installed on a drive that has not been upgraded, even if Windows itself already runs from an SSD. Moving the programs that are actually slow, not just the operating system, is what fixes it.

- id: multiple-drives title: "A desktop with more than one drive, only one of them upgraded" urgency: can-wait urgency_label: "Can wait" price_key: ssd-upgrade-labour-only text: |

It is common for a desktop upgraded a few years ago to have Windows running from an SSD while a second, older mechanical drive still holds games, documents or other files. Windows itself boots fast, but everything stored on the second drive is just as slow to open as it always was, which can make the upgrade feel less effective than it should.

Moving whatever is used often, rather than everything, usually closes that gap without needing a drive as large as replacing the second one entirely. What is worth moving depends on what is actually used day to day, which is easy to work out once we can see the machine.
