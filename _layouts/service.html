--- layout: default --- {%- comment -%} service.html layout for the service page cluster VERSION 1 /laptop-repair-perth first, then the other eight in STATUS.md. Same design as the Tech Tips guides and the industry pages (one centred column, the same type scale, the same dark on-page quote form), so the site reads as one design. css: service in front matter. A guide answers a question; a service page sells the job. So this layout shows a price under each repair, where the guides deliberately do not. PRICES. The page never types one. Every figure comes from services.yml through price.html by key, and the note under each price is that entry's own desc, so a labour-only price is never shown without saying so. FAQ answers write prices as [[service-key]] tokens (front matter cannot run Liquid); resolve-prices.html turns them into figures here, once, and the same resolved text feeds the visible FAQ and the FAQ schema, so the two cannot drift apart. Front matter: Facts slug (must match the file name), heading (H1, breadcrumb and schema name; title is the SEO tag only), eyebrow, service_name (schema serviceType), quote_service (tags the quote email), wa_text (the pre-filled WhatsApp message) Written short_answer, intro (HTML), repairs (each: id, title, price_key, optional also_keys list, text as HTML), faqs (each: q and a) Links suburbs (suburb slugs; a link renders only if that suburb page exists), guides (Tech Tips slugs; built ones only) Optional index_heading (contents box heading, default "What we fix") group on a repair: repairs sharing a group sit under one H2 (the repairs become H3s) and the contents box is grouped the same way. Keep a group's repairs together. group_intros: map of group title to an intro (HTML) signs on a repair: short list shown as "Common signs" sections: extra write-ups after the repairs (each: id, title, html), e.g. repair or replace, brands SEO headings (optional, each with a generic default): costs_heading, faq_heading, near_heading, near_text, topic (lower case, e.g. "laptop repair": names the quote form and guides headings), costs_intro (one or two sentences opening the price section, [[tokens]] allowed). Set them so the section headings carry the page's own search terms. All written HTML (intro, repair text, group intros, sections) may use [[service-key]] price tokens; the layout resolves them. Links out to other service pages come from service_links in _data/suburbs.yml, built: true only, so a service page can never link to one that does not exist yet. {%- endcomment -%} {%- assign _S = site.data.services -%} {%- assign _R = site.data.reviews.meta -%} {%- assign _all = _S.services | concat: _S.addons -%} {%- assign _url = site.url | append: "/" | append: page.slug -%} {%- capture _desc -%}{% include resolve-prices.html text=page.description %}{%- endcapture -%} {%- capture _wa -%}{% include wa-href.html %}{%- endcapture -%} {%- assign _groups = page.repairs | map: "group" | uniq -%} {%- assign _grouped = false -%}{%- if _groups.first -%}{%- assign _grouped = true -%}{%- endif -%} {%- assign _rh = "h2" -%}{%- if _grouped -%}{%- assign _rh = "h3" -%}{%- endif -%} {%- capture _chev %}{% endcapture -%} {%- comment -%} Every price key on the page, in order, once each: the repairs' own keys then their also_keys.
