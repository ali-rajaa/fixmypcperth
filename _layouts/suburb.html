--- layout: default --- {%- comment -%} suburb.html layout for the /suburbs/ cluster Holds only what is genuinely identical on every suburb page: the three schema shells, the contents list, the price table, the quote form, the process steps, the five shared FAQs, the section headings, the link blocks and the JS. Change any of that once and every page follows. Everything that argues the page belongs to its suburb comes from the page's front matter, and all of it is required. The verifier fails a page with any of these missing: Facts suburb, slug (must match the file name), postcode, nearby Travel travel (three cells, each val and lbl), travel_note, cta_title, cta_desc Written why_heading, standfirst, quick_answer, why_local, problems (six cards: title, text, price_key), laptops_intro, desktops_intro, data_intro, local_area, faqs (at least three: q and a) Travel is per suburb because geography is. This layout once hardcoded "sits directly east of Canning Vale, a short run west", which is true of Huntingdale and false everywhere else, including Canning Vale. Rules for the written slots: - No Liquid. Front matter cannot run it, so a price include inside a slot renders as literal text. Prices stay in this layout. - Write, do not reword. The verifier compares every suburb page's written sentences with every other, names swapped, and fails anything over 10% overlap. Eighteen pages differing only by a name is the doorway-page pattern Google penalises. - A problem card's price_key must be a service with a numeric price; one priced as text reads "From Custom". The faqs list feeds both the visible FAQ and the FAQ schema, so the two cannot drift apart. Every price comes from _data/services.yml through price.html, so a price rise stays one edit in one file. {%- endcomment -%} {%- capture _area_default %}{{ page.suburb }}, Western Australia{% endcapture -%} {%- assign _area = page.area_served | default: _area_default -%} {%- assign _diag = site.data.services.services | where: "key", "diagnostic-repair-all-in" | first -%} {%- comment -%} FAQ schema carries only this suburb's own questions (page.faqs), with the same text shown on the page. How a repair works

1

Drop it in, no appointment

Bring the machine to the Canning Vale workshop whenever suits. We take the details and what it has been doing. Bring the charger if it is a laptop, and your Windows login if you have it.

2

Full diagnostic

The machine goes on the bench and gets tested properly rather than guessed at. This is what the flat fee covers, and it happens before anyone quotes you for parts.

3

You hear the price first

We call or message with what is wrong, what it costs and how long it will take. Nothing gets ordered or fitted until you say go.

4

Repair and collection

Most jobs are ready the same day or the next. Anything waiting on a part depends on the part, and you are told that wait up front rather than after. Labour carries a 30 day warranty.
