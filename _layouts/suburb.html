--- layout: default --- {%- comment -%} suburb.html layout for the /suburbs/ cluster Holds only what is genuinely identical on every suburb page: the schema shells, the price list, the quote form, the repair steps, the five shared FAQs, the section headings, the link blocks and the JS. Change any of that once and every page follows. Everything that argues the page belongs to its suburb comes from the page's front matter, and all of it is required. The verifier fails a page with any of these missing: Facts suburb, slug (must match the file name), postcode, nearby, entity (lga list, wikipedia, wikidata) Travel travel (three cells, each val and lbl), travel_checked, travel_note, cta_title, cta_desc Written why_heading, standfirst, quick_answer, why_local, problems (six cards: title, text, price_key), laptops_intro, desktops_intro, data_intro, local_area, faqs (at least three: q and a) Optional: jobs real repairs done for people in this suburb, shown as a grid under the problem cards. Never invent one. Each needs month (YYYY-MM-01), area (the street or estate, never a house number), device, problem, story, outcome, and price_key; photo (640x480) and alt are optional. With no jobs the section is not printed at all. Travel is per suburb because geography is. The drive time and distance are only printed once travel_checked is true, meaning someone has checked them on Google Maps. Until then the box shows the note and the directions link, which gives the real route. Rules for the written slots: - No Liquid. Front matter cannot run it, so a price include inside a slot renders as literal text. Prices stay in this layout. - Write, do not reword. The verifier compares every suburb page's written sentences with every other, names swapped, and fails anything over 10% overlap. Eighteen pages differing only by a name is the doorway-page pattern Google penalises. - A problem card's price_key must be a service with a numeric price; one priced as text reads "From Custom". Collapsed content (the laptop, desktop and data tabs, the extra price rows, the shared FAQs) is all in the HTML on load, so search engines read it. Without JavaScript the tabs show as three plain sections. The faqs list feeds both the visible FAQ and the FAQ schema, so the two cannot drift apart. Every price comes from _data/services.yml through price.html, so a price rise stays one edit in one file. {%- endcomment -%} {%- capture _area_default %}{{ page.suburb }}, Western Australia{% endcapture -%} {%- assign _area = page.area_served | default: _area_default -%} {%- assign _diag = site.data.services.services | where: "key", "diagnostic-repair-all-in" | first -%} {%- assign _ent = page.entity -%} {%- assign _sibs = site.pages | where: "layout", "suburb" | sort: "suburb" -%} {%- comment -%} The business is one entity, defined once by its @id.
